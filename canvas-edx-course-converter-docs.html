Overview

The Canvas to Open edX Course Converter transforms Canvas LMS course exports (.imscc files) into Open edX OLX format, allowing course teams to migrate content from Canvas into MITx on Open edX. It converts course structure, pages, assignments, quizzes, media assets, and grading policies automatically, producing a .tar.gz archive that can be imported directly into Open edX Studio.

Use this tool when a course is being migrated from Canvas to Open edX, or when Canvas course content needs to be repurposed in MITx.

The converter is available as a web application at https://kalebabebe.pythonanywhere.com/ and as a command-line tool for local use.

What Gets Converted

Course Structure

  • Canvas modules → OLX chapters and subsections (sequentials)
  • Wiki pages → HTML components with asset URL conversion
  • Assignments with online text or file upload submission → Open Response Assessments (ORA) with staff grading
  • Assignments with other submission types → HTML info blocks with metadata
  • Quizzes → Problem components (see supported question types below)
  • Canvas front page → info/updates.html (course updates page in Open edX)
  • Assignment groups with percent weighting → Open edX grading policy
  • Module prerequisites → Sequential prerequisites in Open edX
  • Published/unpublished state is preserved for modules and items

Quiz Question Types

Canvas Type Open edX Output Notes
Multiple Choice <multiplechoiceresponse> Full support
True/False <multiplechoiceresponse> Full support
Multiple Response (checkbox) <choiceresponse> Full support
Short Answer <stringresponse> Case-insensitive; supports multiple accepted answers
Numerical <numericalresponse> Supports tolerance ranges
Essay Open Response Assessment (ORA) Staff grading only; basic rubric auto-generated
Matching <optionresponse> Converted to dropdown format
Fill in Multiple Blanks <optionresponse> Converted to dropdown format
Multiple Dropdowns <optionresponse> Full support
Calculated / Formula <numericalresponse> Static conversion using one sample variable set
File Upload Placeholder HTML Instructions to use ORA with file upload
Text Only (no question) HTML component Informational text preserved as-is

Question banks from non_cc_assessments/*.qti are automatically included when referenced by quizzes.

Media and Assets

  • Files from web_resources/ are copied to /static/
  • Image and file URLs are rewritten from $IMS-CC-FILEBASE$ to /static/
  • Panopto LTI embeds are converted to direct Panopto embed iframes (using MIT's Panopto instance)
  • Internal wiki links are converted to /jump_to_id/ links where a matching component exists

What Requires Manual Setup

The converter creates an "Import Notes" chapter at the end of the course listing content that could not be automatically converted:

  • LTI tool integrations (Gradescope, Perusall, etc.)
  • External URL links
  • Discussion topics
  • Timed quizzes (time limits must be configured manually in Open edX Studio under subsection settings → "Timed Examination")
  • Calculated/formula questions use a single static sample, so they may need to be rebuilt as Open edX customresponse problems for dynamic variable generation

Prerequisites

For Web Interface Users (Course Teams)

  • A Canvas course export file in .imscc format (exported from Canvas → Settings → Export Course Content → Course)
  • A web browser
  • Access to Open edX Studio for importing the converted course

For CLI Users (ETs)

  • Python 3.10 or higher
  • The project dependencies installed (see Dependencies section)
  • A Canvas .imscc export file

Using the Web Interface (Course Teams)

Step 1: Export Your Course from Canvas

  1. In Canvas, go to your course → Settings → Export Course Content.
  2. Select "Course" as the export type and click "Create Export."
  3. Download the resulting .imscc file when the export is ready.

Step 2: Convert the Course

  1. Go to https://kalebabebe.pythonanywhere.com/.
  2. Click the upload area or drag and drop your .imscc file onto it.
    • Only .imscc files are accepted. The current maximum file size is approximately 70 MB.
  3. Click "Convert to Open edX."
  4. Wait for the conversion to complete. A progress bar will display during processing.

[SCREENSHOT: The web interface showing the upload area and "Convert to Open edX" button]

Step 3: Review the Conversion Report

After conversion, the tool displays a report with:

  • Course title and ID
  • Conversion statistics (chapters, subsections, units, components, assets copied)
  • Timed quizzes that need manual time-limit configuration in Studio
  • Skipped items that could not be auto-converted, grouped by type

[SCREENSHOT: A sample conversion report showing statistics and skipped items]

Step 4: Download and Import

  1. Click "Download OLX Package" to download the .tar.gz file.
  2. In Open edX Studio, go to your course → Tools → Import.
  3. Upload the .tar.gz file and follow the Studio import prompts.

Step 5: Post-Import Review

  1. Navigate through the course in Studio to verify content converted correctly.
  2. Check the "Import Notes" chapter at the end of the course for items that need manual setup.
  3. For timed quizzes, go to the relevant subsection settings and enable "Timed Examination" with the appropriate time limit.
  4. Recreate any LTI tools, external URLs, or discussion topics manually.
  5. Review essay questions and ORA components to confirm rubrics and settings are appropriate.
  6. Test quiz questions to verify correct answers imported properly.

Using the Command Line (ETs)

Installation

pip install -r requirements.txt

Basic Usage

python -m src.converter course_export.imscc output_directory

Add the --verbose flag for detailed progress output:

python -m src.converter course_export.imscc output_directory --verbose

Python API

The converter can also be used programmatically:

from src.converter import convert_canvas_to_openedx

report = convert_canvas_to_openedx('course.imscc', 'output_dir', verbose=True)
print(report)

To import via CLI, compress the output directory into a .tar.gz archive:

tar -czf course_olx.tar.gz -C output_dir .

After Importing to Open edX

Expected Results

  • Each Canvas module appears as a chapter (section) in Studio.
  • Each module item appears as a unit within its module's subsection.
  • Wiki pages display as HTML components with all images and internal links converted.
  • Quizzes appear as individual problem components (one per question) within a unit.
  • Assignments with online submission types appear as ORA components with staff grading enabled.
  • Panopto videos display as embedded iframes.
  • The Canvas front page content appears on the course Updates page.
  • Grading policy reflects Canvas assignment group weights (if percent weighting was used).

Items That Need Manual Attention

  • Timed quizzes: Time limits are noted in the conversion report and appended to the unit title, but must be configured in Studio under subsection settings → Timed Examination.
  • LTI tools: Gradescope, Perusall, and other external tool integrations must be reconfigured in Studio.
  • Discussion topics: Canvas discussions do not have a direct equivalent and must be recreated.
  • Calculated questions: These are converted using one sample variable set. For dynamic questions, rebuild them as customresponse problems.
  • File upload questions: Converted to placeholder text. Set up ORA with file upload or use a separate assignment.

Troubleshooting

Common Issues

Problem Likely Cause Solution
"File must be .imscc or .zip" Wrong file type uploaded Export from Canvas as "Course" (not "Quiz" or other type). The file should end in .imscc.
Conversion fails during "converting course" Corrupted or non-standard IMSCC file Re-export the course from Canvas. Ensure the export completed successfully before downloading.
Conversion fails during "creating download archive" Disk space exhaustion on PythonAnywhere The file may be too large. Current practical limit is approximately 70 MB. Try exporting without large media files, or use the CLI locally.
Missing images after import Assets not in the Canvas web_resources/ directory Check that images were included in the Canvas export. Externally hosted images (not uploaded to Canvas) will retain their original URLs.
Quiz questions show "[No correct answer specified]" Canvas quiz had no answer key set Edit the problem in Studio and set the correct answer manually.
Import fails in Open edX Studio Malformed OLX XML Check the Studio import error log. Common cause: special characters in content that break XML parsing. Report the issue to mitx-support@mit.edu with the IMSCC file attached.
Panopto videos not playing Video ID not found or permissions issue Verify the Panopto video exists and is accessible. The converter uses MIT's Panopto instance (mit.hosted.panopto.com).

Technical Architecture (Support/Maintenance)

The converter uses a four-stage pipeline architecture:

  1. Parse: CanvasParser extracts the IMSCC ZIP file to a temp directory, then parses imsmanifest.xml, course_settings.xml, module_meta.xml, and assignment_groups.xml. The QTIParser handles quiz files in QTI 1.2 format, including question banks from non_cc_assessments/.
  2. Convert to IR: CanvasToIRConverter transforms the parsed Canvas data into a format-agnostic Intermediate Representation (IR) using dataclasses (CourseIR, ChapterIR, SequentialIR, VerticalIR, ComponentIR). QTIToCapaConverter converts quiz questions to CAPA XML, ORA XML, or HTML. AssetManager rewrites asset URLs and converts Panopto LTI embeds.
  3. Copy assets: AssetManager.copy_all_assets() copies everything from the Canvas web_resources/ directory to the OLX static/ directory.
  4. Generate OLX: OLXGenerator writes the full Open edX OLX directory structure, including course XML, chapter/sequential/vertical hierarchy, HTML and problem files, grading policy JSON, about page, and updates page.

Hosting and Deployment

Currently hosted on PythonAnywhere at https://kalebabebe.pythonanywhere.com/.

PythonAnywhere Details

  • Web app code is located at ~/mitx-canvas-tools-main/ on the PythonAnywhere server.
  • The app runs via WSGI (PythonAnywhere handles this automatically).
  • Temporary files are stored in /tmp/uploads and /tmp/outputs and are cleaned up before each conversion to manage disk space.
  • The Procfile specifies gunicorn app:app --timeout 300 for production use, though PythonAnywhere uses its own WSGI server.

Current Limitations (PythonAnywhere)

  • Practical file size limit is approximately 70 MB due to disk space constraints. The app is configured for a 200 MB max upload, but PythonAnywhere's free/limited disk quota is the real bottleneck.
  • Hosting is planned to move to a different platform in the future, which should remove this limitation.

Deploying Updates

  1. Upload the new code to ~/mitx-canvas-tools-main/ on PythonAnywhere (via the Files tab or git pull if the repo is cloned there).
  2. Go to the Web tab in PythonAnywhere.
  3. Click "Reload" to restart the web app with the updated code.

Common Failure Modes and Diagnostics

Disk Space Exhaustion (PythonAnywhere)

The most common failure in the hosted environment. The app cleans up temp files before each conversion via cleanup_tmp_folders(), and deletes the uploaded file before creating the output archive. If conversions still fail, manually clear /tmp/uploads and /tmp/outputs on the server.

Malformed IMSCC Files

If the IMSCC file is missing imsmanifest.xml, the parser raises a ValueError. If module_meta.xml is missing, the converter proceeds but produces an empty course. Corrupted ZIP files raise a zipfile.BadZipFile exception.

XML Namespace Issues

Canvas exports use the http://canvas.instructure.com/xsd/cccv1p0 namespace, but not consistently. All parsers try namespace-qualified lookups first, then fall back to non-namespaced lookups. If a Canvas update changes the namespace URI, the parsers would need updating.

Quiz Conversion Failures

Individual question conversion failures are caught and logged without stopping the overall quiz conversion. The web interface reports the failure step and error detail in the JSON response. In verbose CLI mode, warnings are printed for each failed question.

Chapter Generation Failures

If a chapter fails to generate, the OLX generator creates a placeholder (staff-only) chapter XML file so that the Studio import does not break due to a missing referenced file.

Gunicorn Timeout

The Procfile sets a 300-second (5-minute) timeout for gunicorn. Very large courses may exceed this. For courses that take longer, use the CLI locally.
